# Gleamory 当前需求与验收规则

> 状态：已实现并持续维护
> 最后更新：2026-07-17

## 1. 产品定位

Gleamory 是个人微产品入口站，目标是：

- 统一展示个人项目和发布状态；
- 为轻量工具提供可直接访问的站内页面；
- 为浏览器插件提供功能、截图、安装和下载说明；
- 以一致的视觉语言形成个人品牌入口。

当前采用纯静态部署，不包含账号、后端、数据库或云同步。

## 2. 信息架构

### 首页

1. 顶部品牌导航。
2. 三图主视觉轮播；仅展示站点标题和简介，不提供跳回首页的链接或项目元信息。
3. 项目列表目录；普通项目按“弦歌有声、丹青拾光、浮生半日”分组展示。
4. 采用共享边线开放式布局的实时月历和每日诗笺。
5. 项目更新时间线。
6. 页脚与 GitHub 入口。

## 3. 业务规则

### 项目目录

- `微光集` 数据项作为首页主视觉的标题与简介来源，不渲染为项目行；简介当前固定为“汇聚所有微光般的创意与灵感”。
- 主视觉轮播图片来自独立配置，当前包含三张本地优化图片；支持上一张、下一张、暂停/继续和键盘方向键。
- 主视觉跨满统一的 90rem 首页内容容器，与右侧栏外沿对齐；使用浅暖纸信息区搭配 16:9 图片视窗，不使用大面积纯黑底。
- 轮播只保留浅色信息区内的一组页码与控制按钮；图片区域不得叠加按钮或分段指示，避免重复操作和遮挡画面。
- 轮播默认每 7 秒切换，鼠标悬停、焦点进入或用户暂停时停止；系统要求减少动态效果时不自动播放。
- 其余项目使用带分类栏的一行一个响应式列表，不渲染矩形卡片背景。
- 分类栏不显示项目数量；分类名称固定为“弦歌有声、丹青拾光、浮生半日”，简介需同时保留典雅语气和实际用途。
- 有 URL 的项目可点击；无 URL 的开发中项目不可点击。
- 分类栏用“卷一、卷二、卷三”建立章节导航；项目行不再重复编号，只显示名称、描述、标签、状态、版本和更新时间。
- 普通项目行不展示封面；主视觉图片由独立轮播配置管理。
- 状态仅允许：`开发中`、`已发布`、`已下线`、`在线`。

### 全局视觉反馈

- 普通文本和输入框文本被框选时，使用实色暖琥珀背景与深墨文字，选中状态不能只依赖低透明度色块。
- 键盘焦点、当前选项和文本框选必须采用不同反馈方式，且在暖纸背景与深色主视觉上都保持清晰对比。

### 时间线

- 数据来自 `src/data/timeline.json`。
- “流光忆庭”只记录新项目上线、核心能力明显扩展、整体重构、重大版本和下线迁移等项目里程碑。
- 样式与文案微调、普通 Bug 修复、依赖或组件实现、测试、CI 和文档同步不得写入时间线，改由 CHANGELOG、提交或 PR 承载。
- 文案面向用户描述能力和阶段，不展示类名、库名、缓存方案等技术实现细节。
- 项目 `updatedAt` 可记录比最近里程碑更晚的有效更新；时间线日期只需不晚于项目更新时间，不要求二者相等。
- 按有效 ISO 日期降序显示。
- 无效日期排在有效日期之后并保持原始相对顺序。
- 默认显示 5 条，可展开全部并收起。
- 前 5 条立即可见；额外记录的展开与收起使用高度和透明度过渡，并遵循系统减少动态效果设置。

### 每日诗句

- 页面宽度达到 1760px 时，月历、诗笺和“流光忆庭”时间线组成右侧栏；主视觉轮播位于分栏上方并跨满整个内容容器。
- 1760px 以下月历与诗词在项目目录下方排列，窄屏恢复为月历在上、诗笺在下；所有模式只使用细分隔线，不渲染独立白底圆角卡片或阴影。
- 三个侧栏模块使用一致的水平内边距、标题基线和整列分隔线，不叠加宽度不一的卡片边框。
- 首先请求今日诗词接口。
- 8 秒超时、接口错误或响应格式错误时使用本地诗词库。
- 组件卸载时取消请求并清除超时器。

### 翻牌抽卡

- 提供二次元角色、扑克牌、扫雷和塔罗牌预设。
- 支持追加、覆盖、去重和保留重复项。
- 每次重建牌组时生成完整且无重复的随机索引。
- 记录当前牌组、翻牌状态、历史和预设到 `sessionStorage`。
- 损坏、旧版或结构不完整的存储数据回退到默认牌组。

### 钢琴与节拍器

- 通过 Web Audio API 在浏览器本地合成声音。
- 音频上下文只能由用户交互触发。
- 页面卸载时必须停止活动声音、清除定时器和关闭音频上下文。
- 键盘事件、窗口事件和文档事件必须在卸载时移除。
- 节拍器路由保持 `#/metronome`，当前版本为 `v1.2.0`，状态保持“在线”。
- 播放按钮右侧提供音量图标；点击后显示 0–100%、步进 1% 的滑杆和百分比，拖到 0% 即静音。
- 音量默认 80%，通过共享主增益实时控制主拍、细分拍和拍点试听；主拍与细分拍保持 2:1 的响度关系，调节时不得重建音频上下文或中断节拍。
- 音量使用 `gleamory:metronome:volume` 保存在 `localStorage`。缺失、损坏、越界或存储不可用时必须安全回退，且不得阻止节拍器使用。
- 音量面板支持键盘操作、外部点击关闭和 Escape 关闭；窄屏下音量按钮保持紧邻播放按钮，计时与轮次允许换到第二行。

### 吉他指板音训练

- 通过首页项目卡片进入，路由为 `#/guitar-fretboard-trainer`，当前版本为 `v0.3.0`，状态保持“开发中”。
- 页面固定为“今日练习”“指板地图”“设置”三个 Tab；0-24 品指板独立位于 Tab 上方。
- 今日练习初始不生成题目。用户选择出题方式、题型与范围后手动生成单题，生成时开始后台计时，答题结束后才展示最终用时和准确率。
- 支持找音、认音、八度、音程和调内音五类题型；随机混合允许限制题型、音名、弦、音程、调性与音级，自选题目允许指定目标参数。
- 单选题准确率为 `0%` 或 `100%`；指板多选题按标准答案集合与用户选择集合的交并比计算部分准确率。
- 练习题必须在指板上标出可选品格范围，范围外位置不可作答；练习中的答案显示不受地图音名自动淡出设置影响。
- 指板地图支持整体或单弦升降半音、把位范围、A-G 指定音多选，以及大调、自然小调、小五声音阶、大三和弦、小三和弦、属七和弦分布。
- 指板点击使用吉他采样音色；左键首次选择并播放、再次左键重复播放、右键取消。当前位置详情独立于临时音名淡出，直到点击下一位置才更新。
- 设置支持调弦预设、玫瑰木/枫木/乌木/高对比四套指板外观、升降号偏好、音名显示模式和点击音名显示时长。
- 本地存储只保存指板设置，不保存逐题结果、每日聚合、练习历史、热力图或技能状态。
- 乐理术语使用延迟浮层解释，鼠标悬停等待 500ms，键盘聚焦或点击立即打开；相关词条允许继续嵌套并通过访问路径阻止循环。

### 音高检测

- 通过首页项目卡片进入，路由为 `#/pitch-detector`，当前版本为 `v0.5.0`，状态保持“开发中”。
- 支持麦克风和屏幕/标签页音频实时检测；浏览器权限拒绝、没有音频轨道或不支持录制时必须显示可理解的恢复提示。
- 存在多个音频输入时，实时检测必须列出可用麦克风，并允许用户在开始前选择系统默认项或指定设备；设备拔插后列表应刷新，失效选择回退为系统默认。
- 支持上传浏览器可解码的音频文件，文件不超过 100 MB、时长不超过 10 分钟，解码和分析只在本地完成。
- 上传轨迹应使用适合离线人声的检测阈值和平滑策略，短清音间隔可在约 220 ms 内保持视觉连续；仍需在明显音高跳变和更长无声区间断开。
- 上传音频播放时使用动画帧同步播放头，空格键可播放或暂停；表单控件与键盘主动聚焦的按钮继续保留标准空格行为。
- 检测结果展示音名、频率、音分偏差、置信度和随时间变化的曲线；曲线支持缩放、拖动和点击定位。
- 实时检测保留最近 180 秒曲线；可用时仅在当前会话保存录音片段供点击回放，不写入持久化存储。
- 麦克风采集关闭面向语音的回声消除、自动增益和浏览器降噪，避免切断持续乐器音；环境降噪默认使用本地带通滤波和噪声门，用户可在开始前关闭。
- 实时检测约每 40 ms 生成一个点，并桥接不超过约 240 ms 的短丢帧；稳定器必须降低同一音高的小幅抖动，同时允许真实换音及时生效。
- 实时检测页使用空格键快速开始或暂停录制，并阻止页面随空格滚动；鼠标点击按钮后残留的焦点不能让空格重复激活该按钮，键盘主动聚焦的按钮以及输入框、下拉框和滑块仍保留标准键盘操作。
- 实时曲线填满当前 X 轴后，最新输入点必须保持在视口中部；曲线下方提供双手柄时间轴范围条，左右手柄分别调整可视起点和终点，中段拖动平移当前范围，且曲线滚轮缩放后范围条必须同步更新。
- 实时回放与上传播放提供播放位置跟随开关；启用后视口随播放竖线平移，用户关闭开关、拖动曲线、拖动范围条中段或任一手柄后必须停止自动跟随。缩放操作保持跟随状态，并以新的可视跨度继续跟随。
- 实时采集游标、实时录音回放和上传播放统一使用动画帧刷新位置；音高分析仍按约 40 ms 步长运行，游标不得因此只按检测帧跳动。从实时回放继续采集时必须暂停旧录音、关闭播放位置跟随，并立即把游标和视口恢复到最新采集时间。
- 播放跟随期间，媒体时间与视口必须在同一动画帧批次内更新；低频 `timeupdate` 不得再并行写入播放游标。数值未变化的视口不得触发曲线重算，长音频播放时应复用可见点、纵轴范围和路径计算结果。
- 暂停实时检测后生成可回放录音；播放按钮和曲线点击都必须以音频实际开始播放为准更新状态。
- 多次开始、暂停产生的录音必须按会话独立保存，不能直接拼接不同 WebM 容器；回放和曲线点击应映射到对应会话，并允许连续播放后续片段。
- 曲线遇到超过 3 个半音的相邻跳点或异常时间间隔时必须断开路径，不能用竖直或长斜线暗示不存在的连续滑音。
- 曲线纵轴使用对数音高比例，音名不得重叠；纵轴音名支持键盘或点击播放本地钢琴参照音。
- 音轨分离完成后的分轨可直接转交音高检测，临时 Blob 只在当前页面会话内传递，读取后立即释放传递记录。
- 页面卸载时停止媒体轨道、取消动画帧、断开音频节点、关闭实时 AudioContext 并释放对象 URL。
- 实时媒体采集只允许在有效 HTTPS 或 localhost 安全上下文中运行；API 缺失时显示 HTTPS 或浏览器兼容性提示，不能暴露原始 TypeError。
- 音高算法必须遵守调用方置信度阈值，能在较强上方谐波与直流偏置下识别基频；非空短片段即使短于默认 4096 帧也应至少尝试一次检测。

### 音轨分离

- 通过首页项目卡片进入，路由为 `#/audio-separator`。
- 音频文件只在浏览器本地解码和推理，不上传到远端服务。
- 模型下载后缓存在 IndexedDB；下载中的单个模型必须允许取消。
- 分轨卡片默认可折叠，展开后选择、下载或删除模型缓存。
- 选中某个分轨的模型即表示输出该分轨；取消选中即不输出。
- 未缓存模型不可选中，也不可开始处理。
- 处理日志独立于上传区，失败后必须保留可读错误信息。
- 处理完成后每个输出分轨提供播放预览和 WAV 下载。
- HT-Demucs 是当前高质量主线，已适配 `vocals`、`drums`、`bass`、`other` 四分轨。
- UVR / MDX 是候补增强路线，只有完成浏览器 ONNX 兼容验证后才可作为普通模型暴露。

#### 音轨分离模型路线

| 路线                | 当前状态       | 说明                                                                                 |
| ------------------- | -------------- | ------------------------------------------------------------------------------------ |
| Spleeter 2-stem     | 快速模式保留   | 体积小、速度快，但分离质量一般，作为轻量兜底。                                       |
| HT-Demucs FT ONNX   | 当前高质量主线 | 支持人声、鼓、贝斯、伴奏四分轨；使用 44.1kHz stereo waveform chunk + overlap-add。   |
| UVR MDX-Net         | 候补路线       | 当前接入 `UVR_MDXNET_KARA_2.onnx` 作为候补测试模型；效果和浏览器兼容性需要继续验证。 |
| UVR MDXC / Roformer | 后续候选       | 常见权重未必是浏览器可直接运行的 ONNX，需要先验证格式、算子和预/后处理。             |

#### 模型下载与部署约束

- 仓库不提交 ONNX 权重；模型清单、下载顺序和本地回退路径以 `src/lib/onnx/modelRegistry.ts` 为准。
- ONNX Runtime WASM 必须由锁定的 `onnxruntime-web` 依赖随构建生成，不在 `public/` 中提交手工复制的运行时文件。
- Spleeter 必须使用固定版本的公开远程源，按主站、镜像、可选本地文件的顺序回退；不得使用可漂移的 `main` 链接代替固定提交。
- 开发环境可使用 Vite 同源代理 `/model-proxy/uvr/<model>.onnx` 解决 GitHub Release 的 CORS/重定向问题。
- GitHub Pages 生产环境没有 Vite 代理，不能依赖 `/model-proxy/uvr/`。
- 生产构建下 UVR 下载源应优先使用可公开访问的远程模型地址，再尝试静态 `/models/uvr/` 兜底。
- 如果 UVR 路线效果确认值得保留，建议将模型迁移到稳定对象存储或明确支持跨域下载的模型托管源。
- 每个模型应记录来源、固定版本、精确大小、校验值和许可信息；不明确的权重许可不得从仓库重新分发。
- 下载内容必须校验：HTML 错误页、Git LFS pointer、过小或截断文件都应视为失败并清理缓存。

### 插件说明页

- 展示名称、版本、功能、截图、安装步骤、使用步骤和下载入口。
- 外部链接在新窗口打开，并使用 `noopener noreferrer`。
- 使用结构化 React 节点渲染步骤，不使用不受控 HTML 注入。
- 截图灯箱支持点击、Enter、Space、Escape 和方向键。

## 4. 数据结构

项目与时间线类型定义以 `src/types/index.ts` 为准。新增数据必须：

- 使用唯一 ID；
- 使用有效路由或 HTTPS 地址；
- 与状态联合类型一致；
- 使用 ISO 日期，未知日期使用 `-`；
- 项目时间线的 `projectId` 对应已存在项目。

## 5. 视觉与响应式

- 整体为暖纸、琥珀和墨黑配色。
- 首页、普通功能页及其顶部站点标识使用同一个居中的标准容器，最大宽度 90rem；指板训练、音高检测及其顶部站点标识使用同一个宽屏容器，最大宽度 100rem。页面不得自行增加第三套横向边距。
- 主题值统一从 `src/styles/globals.css` 获取。
- 字体采用本地三层体系：思源宋体派生的 `Gleamory Editorial` 用于品牌、标题、诗词；思源黑体派生的 `Gleamory UI` 用于正文、控件与提示；Source Code Pro 派生的 `Gleamory Mono` 仅用于数字、时间、坐标、版本、日志和代码。
- 仅使用已提供的 400/500/600 字重并设置 `font-synthesis: none`；不使用 650/750、700 或中文斜体，不以 `system-ui`、LXGW WenKai、KaiTi 或外部字体服务作为主要来源。
- 中文界面文字最小 12px；仅短数字和单位的图表刻度允许 11px/16px。长正文使用 16px/28px，诗词使用 20–24px、500、1.85 行高，页面标题使用 32–48px、600。
- 移动端保持单列和可触控，桌面端使用 70% 左右内容宽度。
- 尊重 `prefers-reduced-motion`。
- 键盘焦点必须清晰可见。

## 6. 性能与资源

- 非首页路由必须独立分包。
- 不提交未使用的静态资源。
- 项目封面优先使用 WebP，分享图使用 1200×630 JPG。
- 中文字体必须使用子集化 WOFF2，不使用完整 OTF。
- 六份 WOFF2 的当前运行时字符、文件哈希和体积必须通过 `npm run check:fonts`；UI Regular 与 Editorial Medium 覆盖完整 GB2312，固定字重覆盖当前运行时字符，Mono 不包含中文。
- 字体分发必须保留 OFL 元数据、可部署许可证与第三方声明；派生 family 不得继续使用官方 Reserved Font Name。完整 OTF/TTF 不提交仓库，不新增运行时字体依赖。
- 首页不应因未访问的钢琴、节拍器或插件页面加载对应业务代码。

## 7. 交付验收

每次发布必须满足：

```bash
npm test
npm run lint
npm run check:fonts
npm run build
```

并人工确认：

- 首页和全部公开 Hash 路由可访问；
- 页面返回后标题恢复为 `Gleamory 微光集`；
- 项目封面、字体、插件截图和 OG 图片可加载；
- 正文、按钮、输入框、下拉框和提示文字落到本地 `Gleamory UI`，标题与诗词落到 `Gleamory Editorial`，数字坐标和代码落到 `Gleamory Mono`，页面不发起外部字体请求；
- 动态中文场景在 GB2312 范围内不得逐字回退系统字体，新增运行时字符、字体哈希和资产体积通过字体门禁；
- 抽卡、钢琴、节拍器、音高检测和指板音训练的主要交互可用；
- 桌面和移动宽度无明显布局回归。

GitHub Actions 只有在测试、Lint 和构建全部通过后才允许部署。
